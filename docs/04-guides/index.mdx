Most changes to Starlet are local to one file. These five are not: each one
crosses a crate boundary, and each one has at least one step that fails
*silently* if you skip it. Every guide below is a checklist with the exact
`path:line` to touch, in dependency order, plus the test that catches the
omission.

Read [Architecture](/architecture) first if you have not — the layering rule
(dependencies point downward, nothing below `ui` knows a window exists) is what
makes these checklists the length they are.

## Ground rules that apply to all five

::::warning[Three things that bite in every one of these changes]
- **Positional decoding.** `RepoRow` is decoded by index, not by name
  (`crates/store/src/repos.rs:40-63`). A column added to the SELECT but not to
  the struct at the same position mis-decodes rather than erroring.
- **A parser that runs on every keystroke must be total.** `query::parse`
  cannot fail and cannot panic (`crates/core/src/query.rs:139`); a new prefix
  either becomes free text or is skipped.
- **A stale async answer must be discarded, not applied.** Any view result that
  depends on the query has to re-check the revision counter
  (`crates/ui/src/search.rs:295`). See [Runtime](/architecture/runtime).
::::

The task runner is `just`; the toolchain is pinned in `rust-toolchain.toml` and
named nowhere else. Every guide's `## Verify` section uses
`just test-crate <name>` and `just test-one <filter>`. The full test map is in
[Testing](/development/testing).
